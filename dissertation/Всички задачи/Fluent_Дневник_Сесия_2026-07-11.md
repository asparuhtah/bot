## 1. Нова топология (добавена тръба за изход на топъл буфер)

Освен старите Drive/Chilled/Solar кръгове, сега има пълна buffer архитектура:

### Cell Zones (Solid, нарочно — pipe walls + lumped thermal mass)
`chiller`, `cold_buffer`, `coldbufferreturn`, `coldbuffersupply`, `hot_buffer`, `hotbufferreturn`, `hotbuffersupply`

### Cell Zones (Fluid)
`cw`, `cw1`, `hw`, `hw1`

### Boundary Conditions
| Граница | Тип | Роля |
|---|---|---|
| `hw_ret` | velocity-inlet | буфер→чилър, drive кръг вход |
| `hw_sup` | pressure-outlet | чилър→буфер, drive кръг изход |
| `cw_ret` | velocity-inlet | буфер→чилър, chilled кръг вход |
| `cw_sup` | pressure-outlet | чилър→буфер, chilled кръг изход |
| `cw_outlet` | pressure-outlet | производство на студ (реален изход към сградата, target по производител) |
| `down_inlet` / `mid_inlet` / `up_inlet` | velocity-inlet | 3 нива на зареждане на hot_buffer от соларите (стратификация) |
| `hw_outlet` | pressure-outlet | връщане към соларните колектори (затваря соларния контур) |

**Важно:** mid_inlet/up_inlet нарочно са зададени на 0 kg/s в момента — първи режим тества само `down_inlet`, другите два ще се пуснат в следващи режими.

### Named Expressions (потвърдени коректни, без промяна нужна)
```
mdot_hw = 0.694 [kg/s]      (= 2500 l/h ✓)
mdot_cw = 0.8056 [kg/s]     (= 2900 l/h ✓)
Thw_ret_avg = AreaAve(StaticTemperature, ['hw_ret'])
Thw_sup_avg = AreaAve(StaticTemperature, ['hw_sup'])
Tcw_ret_avg = AreaAve(StaticTemperature, ['cw_ret'])
Tcw_sup_avg = AreaAve(StaticTemperature, ['cw_outlet'])
Qgen_CFD = mdot_hw * 4182 * (Thw_ret_avg - Thw_sup_avg)
Qevap_CFD = mdot_cw * 4182 * (Tcw_ret_avg - Tcw_sup_avg)
COP_CFD = Qevap_CFD / Qgen_CFD
COP_expr =ピecewise функция по Thw_sup_avg (крива на производителя, за сравнение)
```
Проверка при номинални стойности: Qgen≈17.4kW, Qevap≈10.1kW — съвпада добре с Excel (16.67/10.00 kW).

## 2. Mesh Quality сага

### Проблем 1 — hot_buffer (решен ✅)
- Открит чрез: Domain → Mesh → Quality ▾ → `Minimum Orthogonal Quality = 0.0766` / `Maximum Aspect Ratio = 112.7` на zone 15797 (hot_buffer), координати `(0.0692, 0.3925, 1.2942)` и `(-0.0678, 0.3961, 1.1396)`
- Причина: sliver клетки на прехода тръба↔резервоар (новата геометрия), клетките граничат с fixed boundary → node-smoothing (`mesh/repair-improve/improve-quality`) не помага на AR стойността
- **Фикс:** Add Local Sizing (BOI) в Fault-Tolerant Meshing workflow → Objects: `hotbufferreturn`, `hotbuffersupply` → Maximum Size 5mm → Generate Volume Mesh наново
- **Резултат:** Min Orthogonal Quality 0.0766 → **0.1619**, Max Aspect Ratio 112.7 → **21.98** ✅
- Клетки: 905 884 → 1 016 040

### Проблем 2 — chiller / cold_buffer (частично адресиран ⚠️)
- След regenerate, нов проблем изплува на **различна** локация: zone 15855 (chiller) Min OQ=0.0922 при `(-0.6263, 0.8616, 1.6856)`; zone 15852 (cold_buffer) Max AR=88.7 при `(-1.1948, 1.2696, -0.1296)`
- Solver-side smoothing (`mesh/repair-improve/improve-quality`, limit 0.2): Min OQ 0.0922→**0.1035** (леко подобрение), Max AR **непроменено на 88.7453** (same cell, boundary-locked, идентично на предишния модел)
- Опит за фикс: BOI с Maximum Size 15mm на цели тела `chiller`+`cold_buffer` → **удари Student лиценз лимита** (виж т.3) → сесията гръмна, наложи се revert
- **Статус:** оставено както е (0.1035 / 88.7) — cold_buffer/chiller са Solid зони (само conduction), по-толерантни на лош AR от fluid зони. Решено да не се харчи клетъчен бюджет, докато не се потвърди реален проблем (temperature clipping) точно там по време на solve.

### Потвърден твърд лимит на Student лиценза
```
"This is a student license, and can only be used with meshes 
containing less than 1048576 cells or 1048576 unmeshed faces."
```
**1 048 576 клетки** (= 2^20) — точното число. По-старият запис "512k" в дневника е неточен/остарял, да се коригира занапред. При последната работеща мрежа (1 016 040 клетки) остава резерв само ~32 500 клетки.

## 3. Solve резултати (300 → 800 итерации)
