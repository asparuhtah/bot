## 7. Откриване на истинската коренна причина

**Проверка на реални обеми** (Report → Volume Integrals → Volume):
```
hw1 = 1.0161622 m³        cw1 = 0.07999603 m³
hw  = 0.076104197 m³      cw  = 1.0140218 m³
```

**Критично съвпадение:** `hw1` source term-ът използваше denominator `0.076104197 m³` — това е ТОЧНО обемът на `hw`, не на `hw1`! Разлика 13.35x. Междувременно `cw1` source term-ът коректно използваше `0.07999603 m³` — точно собствения обем на `cw1`.

**Потвърждение чрез проверка на конфигурацията:** source term-ът действително беше физически приложен върху зона `hw` (не `hw1`), с формула `-Qgen_CFD_safe/0.076104197[m^3]` — числено коректна за `hw` самата, но приложена върху грешна (несвързана) зона спрямо тази, чиито граници (`hw_ret`/`hw_sup`) реално следим.

**Финално потвърждение:** Mesh interface `intf:02:hw1.1::hw.1` показа **Area = 0.0000%** — `hw1` и `hw` нямат никаква реална mesh/термична връзка. Sink-ът на `hw` физически не можеше да повлияе на `hw1` изобщо.

**Асиметрията обяснена:** `cw1` (студената страна) е имал sink-а правилно на себе си от самото начало (`cw` няма source term) — затова студената страна се държеше разумно цял ден, докато горещата — хаотично, независимо от всички други променливи тествани (mesh, материали, numerical settings).

## Текущи Solution Methods настройки (край на деня)

```

Spatial Discretization: Gradient = Least Squares Cell Based, останалите = Second Order (Upwind за momentum/k/omega/energy)
Pseudo Time Method: Global Time Step
  Fluid Time Scale Factor = 1
  Solid Time Scale Factor = 1.0  (финална стойност — 1.5 и 3 доведоха до растящи residual-и)
Warped-Face Gradient Correction: ON
Autosave: every 50 iterations, filename prefix "Regime1_lowk_500iter"
```
